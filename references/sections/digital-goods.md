# Цифровые товары (`digital-goods`)

API цифровых товаров — набор методов для продавцов, которые продают на Авито цифровые товары (коды активации, ключи, промокоды, подписки).
Через API можно получать заказы покупателей, отправлять цифровой товар, отменять заказ, эскалировать спор в арбитраж, выводить средства и подписаться на уведомления об изменении статуса заказа через webhook.
**Авито API для бизнеса предоставляется согласно [Условиям использования](https://www.avito.ru/legal/pro_tools/public-api).**

# API цифровых товаров

API для продавцов, которые продают на Авито цифровые товары — коды активации, ключи, промокоды, подписки. Через него можно забирать оплаченные заказы, отправлять товар покупателю, отменять заказ, эскалировать спор в арбитраж, выводить деньги и получать уведомления об изменении статуса заказа.

- **Базовый URL (prod):** `https://api.avito.ru/digital-goods/`
- **Версия:** v1
- **Формат:** JSON
- **Авторизация:** OAuth 2.0 client credentials — см. [документацию auth](https://developers.avito.ru/api-catalog/auth/documentation)

---

## Быстрый старт

Понадобится access token — как его получить, описано в [документации auth](https://developers.avito.ru/api-catalog/auth/documentation). Все методы работают только с заказами того продавца, которому выданы ключи.

### 1. Заберите заказы, ожидающие отправки

```bash
curl --request GET \
  --url 'https://api.avito.ru/digital-goods/v1/orders?statuses=in_progress' \
  --header 'Authorization: Bearer ВАШ_ТОКЕН'
```

### 2. Отправьте товар покупателю

```bash
curl --request POST \
  --url https://api.avito.ru/digital-goods/v1/orders/019a5dc0-0677-7f77-b0a6-e99dd3b68fa1/send \
  --header 'Authorization: Bearer ВАШ_ТОКЕН' \
  --header 'Content-Type: application/json' \
  --data '{"product": "Код активации: CODE-123-456"}'
```

Текст из `product` уходит покупателю в чат по заказу, заказ переходит в статус `sent`.

## Жизненный цикл заказа

| Статус | Что произошло | Что может продавец |
| --- | --- | --- |
| `in_progress` | Покупатель оплатил заказ, деньги удерживаются Авито | Отправить товар (`/send`) или отменить заказ (`/cancel`) |
| `sent` | Товар отправлен, идёт срок на подтверждение покупателем | Ждать подтверждения |
| `dispute` | Покупатель открыл спор | Договориться в чате или эскалировать в арбитраж (`/escalate-to-arbitration`) |
| `arbitration` | Спор передан в арбитраж Авито | Ждать решения арбитра |
| `completed`, `completed_by_buyer`, `completed_by_avito`, `completed_by_arbitrator` | Заказ завершён, деньги разблокированы | Получить ссылку на вывод средств (`/payout`) |
| `canceled`, `canceled_by_buyer`, `canceled_by_seller`, `canceled_by_avito`, `canceled_by_arbitrator` | Заказ отменён, деньги вернулись покупателю | — |

Терминальность статуса продублирована в ответе в поле `status.terminal`, человекочитаемое название — в `status.title`.

Действия недоступны в неподходящем статусе: `/send`, `/cancel`, `/escalate-to-arbitration` и `/payout` вернут `409`, если заказ уже перешёл дальше по жизненному циклу.

### Чаты по заказу

В заказе два независимых поля с чатами:

- `chat_id` — чат продавца с покупателем по заказу;
- `chat_with_arbitrator` — чат продавца с арбитром. Появляется только после того, как заказ попал в арбитраж. Арбитр создаёт чат не мгновенно, поэтому сразу после `/escalate-to-arbitration` поле ещё может быть `null` — запросите заказ повторно чуть позже. Чат арбитра с покупателем в API не отдаётся.

## Уведомления (webhook)

Чтобы не опрашивать `/v1/orders` по расписанию, подпишитесь на уведомления об изменении статуса заказа.

### Подписка

```bash
curl --request POST \
  --url https://api.avito.ru/digital-goods/v1/webhook \
  --header 'Authorization: Bearer ВАШ_ТОКЕН' \
  --header 'Content-Type: application/json' \
  --data '{
    "url": "https://seller.example.com/digital-goods/v1/orders/events",
    "secret": "f9c2a7d4e8b1c6a3f0d9e2b5a8c1d4f7"
  }'
```

Подписка одна на аккаунт: повторный вызов перезаписывает ранее сохранённые `url` и `secret`. Отписаться — `DELETE` на тот же адрес.

### Что приходит

На указанный `url` отправляется `POST` с телом:

```json
{
  "order_id": "019a5dc0-0677-7f77-b0a6-e99dd3b68fa1",
  "status": "dispute",
  "occurred_at": "2026-07-03T09:15:00Z"
}
```

Заголовки запроса:

- `Content-Type: application/json`
- `X-Secret` — значение `secret`, переданное при подписке. Сверяйте его на своей стороне и отклоняйте запросы с чужим или отсутствующим секретом.

Уведомление содержит только идентификатор заказа и новый статус — за подробностями сходите в `GET /v1/orders/{order_id}`.

### Требования к обработчику

- Отвечайте любым кодом `2xx`. Любой другой ответ или таймаут считается неуспехом, доставка будет повторена.
- Обрабатывайте уведомления идемпотентно: повтор доставки может привести к дублю по одному и тому же `order_id` и `status`.
- Уведомления не гарантируют порядок доставки — ориентируйтесь на `occurred_at`, а актуальное состояние сверяйте запросом заказа.
- Если подписка была удалена между событием и доставкой, уведомление не отправляется.

Если уведомления были пропущены, историю переходов заказа можно восстановить через `GET /v1/orders/{order_id}/history`.

---

## Ограничения

- В списке заказов `limit` не больше `100`; для обхода большой выборки используйте `offset` и признак `pagination.hasMore`.
- Фильтры-списки (`statuses`, `item_ids`, `buyer_ids`) передаются одним параметром через запятую.
